## Executive Summary

# Testing Reticulum: Building a Decentralized Mesh Network from House to World

## Overview

This video documents an ambitious real-world test of **Reticulum**, an open-source internet protocol that enables mesh networking without traditional ISPs. The creator progressively tests the technology's range capabilities across four escalating distances: across a house, throughout a neighborhood, across a city, and ultimately from Florida to Venezuela. The goal is to determine whether Reticulum can realistically provide a viable alternative to centralized internet infrastructure.

## Test 1: House Test - Proving the Concept

**Hardware Setup:**
- **Base Node:** Green Haven node (Raspberry Pi running OpenMana/OpenWRT) with WiFi Halow (sub-gigahertz 900 MHz) capability
- **Mobile Node:** Heltec HD-T01 (compact Linux board with Halow radio)
- **Client Software:** MeshChat (desktop) and Sideband (Android app)
- **Key Feature:** Reticulum runs on clients, not routers - the mesh network just provides connectivity

**Results:**
- Successfully sent text messages, voice notes, and images across the house
- Messages delivered instantly with stable connection
- Power consumption: less than 1 watt for mobile node
- WiFi Halow bandwidth: 1-3 Mbps on 1 MHz channel (optimized for range over speed)

**Important Note:** The creator demonstrates connecting an iPhone directly to the mesh node via USB-C to Ethernet, showing the flexibility of the setup.

## Test 2: Neighborhood Test - Extending the Range

**Preparation:**
- Installed external 9 dBi fiberglass antenna outside the house to overcome concrete brick obstruction
- Mounted antenna approximately 20-30 feet high using tension mount (no drilling required)
- Used BNC to SMA adapter to connect external antenna to Haven node

**Mobile Setup:**
- Magnetized antenna mount on Tesla vehicle
- Heltec node powered by car's 12V outlet
- Android phone running Sideband connected via WiFi (not Ethernet)

**Results:**
- **1,000 feet:** Message delivered successfully
- **1,400-1,500 feet:** Continued successful transmission
- **~2,000 feet:** Signal failed - reached practical limit for this configuration

**Key Insight:** WiFi Halow struggled with dense cement brick houses in the neighborhood, highlighting the importance of line-of-sight and elevation.

## Test 3: City Test - Switching to LoRa

**The Challenge:**
Initial attempts with WiFi Halow and aerial deployment (kite/drone) at 4+ miles failed due to:
- Intermittent connectivity (signal spotted briefly every 10 seconds)
- Lack of adequate elevation compared to previous Miami high-rise tests
- Concrete construction blocking signals

**Technology Pivot:**
Switched from WiFi Halow to **LoRa radios** because:
- LoRa can operate below the noise floor
- More configurable parameters (spreading factor, coding rate, bandwidth)
- Better penetration through obstacles
- Trade-off: Lower bandwidth, but adequate for text messaging

**LoRa Configuration:**
- Two Heltec V4 boards running 27 dBm
- Bandwidth: 125 kHz
- Spreading factor: 12 (maximum for range)
- Coding rate: 8
- R-node software for Reticulum interface

**Testing Process:**
Multiple attempts in neighborhood failed due to cement brick density. Final test conducted on open straightaway road for better line-of-sight.

**Results:**
- **0.5 miles:** Successful (RSSI: -44, SNR: 5 dB)
- **1 mile:** Successful (RSSI: -85, SNR: -3.2)
- **2 miles:** Successful with line-of-sight (RSSI: -91, SNR: 4 dB)
- **3.4 miles:** Successful (SNR: -6.2) - maximum achieved distance
- **3.5 miles:** Signal dropped, then reacquired at ~3 miles on return trip

**Critical Finding:** Line-of-sight proved more important than antenna elevation for LoRa performance.

## Test 4: Global Test - Florida to Venezuela

**The Math Problem:**
- Distance Florida to California: 2,500 miles
- At 3.5 miles per hop: **800 nodes required**
- Conclusion: Pure radio mesh impractical for continental distances

**The Solution: Tailscale Mesh VPN**

**Key Concept:** Reticulum is protocol-agnostic - it doesn't care what carries the data (WiFi, Ethernet, LoRa, or even theoretically Morse code).

**Tailscale Implementation:**
- Creates private encrypted mesh VPN
- Connects disparate local mesh networks via encrypted tunnel
- Not public internet - private encrypted network infrastructure
- Alternative open-source options: WireGuard, HeadScale

**Real-World Use Case Demonstrated:**
The creator already uses this setup for video production workflow:
- TrueNAS server in Florida with Tailscale
- Editor in Venezuela connects to private tailnet
- Files appear instantly on editor's machine as if local
- Eliminates cloud storage dependency

**Final Test Setup:**
1. **Origin:** Android phone (no external network) → LoRa Heltec node
2. **Hop 1:** LoRa transmission to desktop R-node in Florida
3. **Hop 2:** Desktop with TCP/IP interface to Tailscale VPN
4. **Tunnel:** Encrypted mesh VPN across internet infrastructure
5. **Destination:** Editor's computer in Venezuela with MeshChat

**Historic Result:**
✅ **Message successfully transmitted from Florida to Venezuela over Reticulum**
- Sent via LoRa radio locally
- Tunneled through private encrypted VPN
- Received on MeshChat in Venezuela
- End-to-end encryption maintained throughout

## Technical Deep Dive

### Why Reticulum Matters

**Advantages Over Traditional Mesh Protocols:**
- **Linear scaling** (not exponential) - doesn't flood network with repeated packets
- **Stores routes** efficiently
- **Protocol agnostic** - works with any data transport layer
- **Cryptographically complete** - encryption by default
- **No central authority** - truly decentralized

**Comparison to Ham Radio:**
- Ham radio requires license (>4W EIRP)
- Ham radio cannot be encrypted (conversations are public)
- Ham radio is analog, not full internet
- Reticulum uses unlicensed ISM band, supports encryption, and provides full IP networking

### Hardware Specifications

**WiFi Halow Characteristics:**
- Sub-gigahertz frequency (900 MHz)
- 1 MHz channel: ~3 Mbps max, best range
- 8 MHz channel: up to 43 Mbps, reduced range
- Better building penetration than 2.4/5 GHz WiFi
- Suitable for IoT, video calls (FaceTime worked perfectly at 1 MHz)

**LoRa Characteristics:**
- Sub-gigahertz operation
- Can decode signals below noise floor
- Highly configurable (spreading factor, bandwidth, coding rate)
- Superior range but lower bandwidth than Halow
- Ideal for text messaging and low-data applications
