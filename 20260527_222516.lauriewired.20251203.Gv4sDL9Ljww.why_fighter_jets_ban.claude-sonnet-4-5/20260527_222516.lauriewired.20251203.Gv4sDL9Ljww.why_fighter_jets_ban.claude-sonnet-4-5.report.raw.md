# GLOSSARY OF ADVANCED TERMS

- GARBAGE COLLECTOR: A garbage collector is an automatic memory management feature in programming languages that identifies and frees up memory that is no longer being used by a program. In high-stakes systems like fighter jets, garbage collectors are avoided because their unpredictable timing could cause dangerous delays during critical operations.
-- Analogy: Like having a cleaning crew that shows up randomly during a surgery to tidy up, potentially interrupting critical moments.
-- Why It Matters: Understanding why certain languages avoid garbage collection helps explain the strict memory management requirements in safety-critical aerospace systems.

- UNHANDLED EXCEPTION: An unhandled exception occurs when a program encounters an error condition that has no recovery code defined, causing the program to crash or behave unpredictably. In the Ariane 5 disaster, an unhandled exception from converting a 64-bit float to a 16-bit integer destroyed a half-billion dollar rocket.
-- Analogy: Like a fire alarm going off in a building with no evacuation plan, causing chaos instead of orderly response.
-- Why It Matters: This concept illustrates why exception handling is either forbidden or extremely controlled in aerospace software standards.

- JSF C++ STANDARD: The Joint Strike Fighter C++ Coding Standard is a set of strict programming rules developed for the F-35 fighter jet that removes dangerous features from C++ to make it safer for mission-critical applications. It represents a "remove before flight" approach where language features are surgically eliminated rather than added.
-- Analogy: Like giving a chef a kitchen with only the essential tools and removing anything that could cause accidents, even if those tools are useful in other contexts.
-- Why It Matters: This standard demonstrates how powerful languages can be made safe through restriction rather than requiring entirely new languages.

- MICROCODE: Microcode is low-level code that is physically burned into hardware chips to control processor operations, sitting between hardware and software. The F-14 Tomcat used microcode burned into a secret microprocessor that predated Intel's 4004, containing about 2,500 lines to process polynomial equations.
-- Analogy: Like instructions permanently etched into the gears of a mechanical watch, controlling its fundamental operations.
-- Why It Matters: Understanding microcode shows the evolution from hardware-based to software-based flight control systems in aerospace.

- SENSOR FUSION: Sensor fusion is the process of combining data from multiple sensors to produce more accurate and reliable information than any single sensor could provide. The F-35 uses sensor fusion as one of its most complex software features, requiring extensive computational power.
-- Analogy: Like combining reports from multiple witnesses to get a clearer picture of an event than any single account could provide.
-- Why It Matters: This concept explains why modern fighter jets require millions of lines of code and why software reliability is paramount.

- MEMORY ALLOCATION: Memory allocation is the process of reserving computer memory space for program data during execution, which can be either static (predetermined) or dynamic (requested as needed). In JSF C++, dynamic memory allocation is severely restricted because unpredictable allocation timing could cause failures during critical flight operations.
-- Analogy: Like the difference between having assigned seats (static) versus first-come-first-served seating (dynamic) on an airplane during an emergency evacuation.
-- Why It Matters: Controlling memory allocation is fundamental to creating predictable, reliable software in safety-critical systems.

- RECURSION: Recursion is a programming technique where a function calls itself to solve a problem by breaking it into smaller instances of the same problem. The JSF standard restricts or prohibits recursion because it can consume unpredictable amounts of memory and processing time.
-- Analogy: Like a hall of mirrors where you see reflections of reflections, which could theoretically continue forever if not controlled.
-- Why It Matters: Understanding recursion restrictions explains how aerospace code maintains predictable execution patterns essential for real-time systems.

- ADA PROGRAMMING LANGUAGE: Ada is a high-level programming language designed in the 1970s-80s specifically for safety-critical and real-time systems, mandated by the Department of Defense for military projects for about 15 years. It emphasizes strong typing and built-in safety features but fell out of favor as C++ gained popularity and Ada compilers were expensive.
-- Analogy: Like a car designed with every possible safety feature built in from the start, making it very safe but also rigid and expensive to operate.
-- Why It Matters: Ada's rise and fall illustrates the tension between safety-focused language design and practical considerations like cost and developer availability.

- MISSION CRITICAL SOFTWARE: Mission critical software is code whose failure would result in the failure of the entire mission or operation, requiring extremely high reliability standards. In fighter jets, this includes flight control systems, navigation, and weapon systems that must function perfectly under all conditions.
-- Analogy: Like the main parachute for a skydiver, where failure is not an acceptable option and backup systems must be in place.
-- Why It Matters: This classification determines which coding standards and verification processes must be applied to software components.

- SAFETY CRITICAL SOFTWARE: Safety critical software is code whose failure could result in loss of life, injury, or catastrophic damage, requiring the highest levels of testing and verification. Flight control software in aircraft is safety critical because failures could directly cause crashes.
-- Analogy: Like the brake system in a car, where malfunction could directly cause fatal accidents.
-- Why It Matters: Understanding this classification explains why aerospace software follows such restrictive coding standards compared to typical applications.

- WEB API: A Web API (Application Programming Interface) is a set of protocols that allows different software applications to communicate over the internet by sending and receiving structured data. X-Plane 12's web API publishes live flight data that external programs can subscribe to for real-time monitoring.
-- Analogy: Like a radio station broadcasting information that multiple receivers can tune into simultaneously.
-- Why It Matters: Web APIs enable the integration of flight simulators with custom instrumentation and testing tools used in aerospace development.

- MULTI-FUNCTION DISPLAY (MFD): A Multi-Function Display is a screen in an aircraft cockpit that can show different types of information like navigation, systems status, or tactical data depending on pilot selection. Modern fighters rely heavily on MFDs to present complex information in a manageable way.
-- Analogy: Like a smartphone screen that can switch between different apps, each showing different types of information as needed.
-- Why It Matters: MFDs represent the interface between complex software systems and pilots, making software reliability directly impact pilot effectiveness.

- HORIZONTAL BIAS: Horizontal bias in the Ariane 5 context refers to a velocity measurement used in the rocket's inertial guidance system to track horizontal movement. The conversion of this 64-bit floating-point value to a 16-bit integer caused an overflow that triggered the fatal exception.
-- Analogy: Like trying to write a very large number into a small box designed for small numbers, causing the system to break.
-- Why It Matters: This specific technical failure demonstrates how data type mismatches can have catastrophic consequences in aerospace systems.

- SWING WING DESIGN: A swing wing (or variable-sweep wing) is an aircraft wing design where the angle of the wings can be adjusted during flight for optimal performance at different speeds. The F-14 Tomcat's swing wing required computer control because manual adjustment during high-G maneuvers would be too complex for pilots.
-- Analogy: Like a car that can change its body shape while driving to be aerodynamic on highways but stable in city traffic.
-- Why It Matters: This design requirement drove early adoption of microprocessors in military aircraft, beginning the software-heavy era of aviation.

- HIGH-G MANEUVERS: High-G maneuvers are aircraft movements that subject pilots and aircraft to gravitational forces many times stronger than normal Earth gravity. These extreme conditions require computer assistance because human reaction time and physical capability are insufficient for optimal control.
-- Analogy: Like trying to pour a glass of water while on a rapidly spinning carnival ride, where normal human coordination breaks down.
-- Why It Matters: The physical demands of modern fighter aircraft make software control systems essential rather than optional.

- STRONG TYPING: Strong typing is a programming language feature that enforces strict rules about how different data types can be used and converted, catching many errors at compile time. Ada's strong typing was designed to prevent the kind of type conversion error that destroyed the Ariane 5.
-- Analogy: Like a filing system that refuses to let you put a square document in a round hole, preventing mistakes before they happen.
-- Why It Matters: Type system strength is a key factor in language safety for critical applications.

- REAL-TIME SYSTEMS: Real-time systems are computing systems that must respond to inputs within strict time constraints, where late responses are as bad as wrong responses. Fighter jet software must process sensor data and execute control commands within milliseconds to maintain flight stability.
-- Analogy: Like a drummer in a band who must hit beats at exact moments, where being even slightly late ruins the performance.
-- Why It Matters: Real-time requirements explain why aerospace software cannot tolerate unpredictable delays from features like garbage collection.

- DENSITY ALTITUDE: Density altitude is a calculated value representing the altitude at which an aircraft "thinks" it is flying based on air density, affecting engine performance and lift. This calculation combines actual altitude, temperature, and pressure to predict aircraft performance.
-- Analogy: Like how your body performs differently at sea level versus on a mountain, even if the thermometer shows the same temperature.
-- Why It Matters: Accurate density altitude calculations are essential for safe flight operations and mission planning.

- V-NAV DATA: V-NAV (Vertical Navigation) data provides guidance for the vertical flight path of an aircraft, calculating optimal climb and descent profiles. This involves complex calculations integrating aircraft performance, fuel efficiency, and air traffic control requirements.
-- Analogy: Like a GPS that tells you not just where to turn, but also when to go uphill or downhill for the most efficient route.
-- Why It Matters: V-NAV calculations demonstrate the type of complex, reliability-critical computations performed by aerospace software.

- FLIGHT ENVELOPE: The flight envelope represents the boundaries of safe aircraft operation defined by combinations of speed, altitude, angle of attack, and other parameters. Software monitors these parameters to warn pilots or prevent maneuvers that would exceed safe limits.
-- Analogy: Like the safe operating zone on a pressure cooker, where staying within the boundaries ensures safety but crossing them risks disaster.
-- Why It Matters: Flight envelope protection systems are safety-critical software that must never fail or provide incorrect data.
